Use this viewer for parsed `event.flamegraph` attachments. Each call tree represents an independent sample population. The selector changes the displayed tree without combining counts across threads.

Existing MetricKit stacktrace flamegraphs continue to use `StacktraceFlamegraph`.

## Find the Hot Path

This synthetic feed-loading example has three independent call trees:

- **Thread 1, responsible thread**: 1,000 samples. Image decoding accounts for 480 samples, making it the largest branch. Hover over `decodeImage` and its system frames to inspect sample counts and source locations. Consider moving decoding off the main thread or caching decoded images.
- **Thread 2**: 600 samples. Repeated database reads dominate background feed hydration. Compare the `loadAuthor` and `loadComments` branches to identify opportunities to batch queries.
- **Thread 3**: 400 samples. Background synchronization splits work between JSON decoding and persistence.

Frame widths represent sample counts, not elapsed time. Parent counts include their children. Samples that end at a parent remain visible without a child frame.

```jsx
<FlamegraphAttachment data={parsedAttachment} />
```

## Props

| Prop   | Type                       | Description                                                                                                     |
| ------ | -------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `data` | `FlamegraphAttachmentData` | Validated version-1 frames and call trees. Use `parseFlamegraphAttachment` at the attachment download boundary. |

The graph reuses the profiling canvas renderer and hover tooltips. The call-tree selector has an accessible label, and the selected tree's sample total is displayed as text.
