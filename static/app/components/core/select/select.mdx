`<Select>` is a dropdown component for choosing one or multiple items from a list of options. It supports searching, clearing selections, custom option rendering with icons, and both single and multi-select modes.

Use `<Select>` for form fields where users need to choose from a predefined set of options. For more complex selection scenarios with sections or custom triggers, consider `<CompactSelect>` instead.

```jsx
<Select
  placeholder="Choose an option"
  options={[
    {value: 'option1', label: 'Option 1'},
    {value: 'option2', label: 'Option 2'},
    {value: 'option3', label: 'Option 3'},
  ]}
/>
```

## Usage Patterns

### Form Fields

Pair selects with labels for accessible forms:

```jsx
<label htmlFor="environment">
  Environment
  <Select
    id="environment"
    placeholder="Choose an environment"
    options={[
      {value: 'prod', label: 'Production'},
      {value: 'staging', label: 'Staging'},
      {value: 'dev', label: 'Development'},
    ]}
  />
</label>
```

### Controlled Selects

For controlled selects, manage the value in React state. `value` and `defaultValue`
use the raw option value, or an array of raw values for multiple selections.
`onChange` receives the selected option, an array of selected options, or `null`
when a clearable single selection is cleared:

```jsx
const [value, setValue] = useState(null);

<Select
  clearable
  value={value}
  onChange={option => setValue(option?.value ?? null)}
  options={options}
/>;
```

### Multi-Select for Tags

Use multi-select for tag or category selection:

```jsx
<label>
  Tags
  <Select
    multiple
    searchable
    clearable
    placeholder="Add tags"
    value={selectedTags}
    onChange={setSelectedTags}
    options={allTags}
  />
</label>
```

## Custom content and menu behavior

Use the select's content props to customize its appearance. The select owns input,
option, and chip behavior; callers do not need implementation components or their props.

| Prop                         | Purpose                                                         |
| ---------------------------- | --------------------------------------------------------------- |
| `components.Value`           | Selected value content. Receives `option`.                      |
| `components.OptionLabel`     | Option label content. Receives `option`.                        |
| `components.MultiValueLabel` | Chip content. Receives `option` and `children`.                 |
| `controlLeadingItems`        | Add content before the value and search input.                  |
| `dropdownIndicator`          | Replace the dropdown icon, or pass `null` to hide it.           |
| `components.Indicators`      | Indicator wrapper. Receives `children`; pass `null` to hide it. |
| `menuFooter`                 | Add content after the options, outside the scroll container.    |
| `virtualized`                | Virtualize a large list, including grouped options.             |

Pass component types in `components`, for example:

```tsx
<Select options={options} components={{Value: FruitValue, Indicators: FruitIndicators}} />
```

Option components receive the full option as their `option` prop.
`MultiValueLabel` receives the default label as `children`, and `Indicators`
receives the default indicator controls as `children`. Define these components
outside the parent component so they keep the same identity between renders.

Set `isOpen` and `onOpenChange` to control the menu. The component `ref` exposes
`focus()` and `blur()`. Use `inputRef` to access the native search input.

Single selects blur after selection by default; multiple selects keep focus.
Set `blurInputOnSelect={false}` when focus must remain in the field, such as
while saving a form. `openMenuOnClick` and `openMenuOnFocus` control whether
those interactions open the menu; keyboard opening remains available.

Fetch remote options outside the select, then pass `options`, `isLoading`, and
`onInputChange`. Set `filterOption={null}` when the server performs all filtering.
`options` is required. Pass `options={[]}` when no options are available, including
for creatable selects without predefined choices.
`onInputChange(input, reason)` reports user edits with `reason="input"` and text
cleared by selection, blur, or menu close with `reason="reset"`. Ignore resets
when a remote query must keep its search term. Custom `filterOption` callbacks
receive the option and search text directly. The select does not fetch or cache options.

## Accessibility

`<Select>` is built with accessibility in mind and meets WCAG 2.2 AA standards:

- [2.1.1 Keyboard](https://www.w3.org/TR/WCAG22/#keyboard): Full keyboard navigation with arrow keys, Enter, Escape
- [2.4.7 Focus Visible](https://www.w3.org/TR/WCAG22/#focus-visible): Clear focus indicators

The component follows the [WAI-ARIA Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) and [Listbox](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/) patterns, including:

- `role="combobox"` on the input
- `aria-expanded` state management
- `aria-controls` linking to the options list
- `aria-activedescendant` for keyboard navigation
- Screen reader announcements for selection changes

### Developer Responsibilities

**Labels** ([WCAG 3.3.2](https://www.w3.org/TR/WCAG22/#labels-or-instructions))

- Every select must have an associated label
- Use a `<label>` element with `htmlFor`, wrap the select in a `<label>`, or provide `aria-label`
- In-field labels (`inFieldLabel`) supplement but don't replace proper labeling

```jsx
// Good: Visible label with htmlFor
<label htmlFor="project">Project</label>
<Select id="project" options={projects} />

// Good: Wrapping label
<label>
  Project
  <Select options={projects} />
</label>

// Good: aria-label when context is clear
<Select aria-label="Filter by project" options={projects} />
```

**Keyboard Navigation**

- **Arrow Up/Down**: Navigate options
- **Enter/Space**: Select option or open dropdown
- **Escape**: Close dropdown
- **Type to search**: When `searchable` is enabled

**Error Handling**

- Use `aria-invalid` and `aria-describedby` for validation errors
- Provide clear, specific error messages

```jsx
<Select
  id="project"
  options={projects}
  aria-invalid={hasError}
  aria-describedby={hasError ? 'project-error' : undefined}
/>;
{
  hasError && (
    <span id="project-error" role="alert">
      Please select a project
    </span>
  );
}
```

For more information, see the [WAI-ARIA Combobox practices](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/).
