Sentry's form system is built on top of [TanStack Form](https://tanstack.com/form/latest), a headless, type-safe form library for React. Because TanStack Form is headless, it handles form state, validation, and submission without imposing any UI — our system layers Sentry's field components, layouts, and accessibility patterns on top.

Validation is schema-driven with [Zod](https://zod.dev/). You define a single schema for your form, and the system takes care of field-level validation, error messages, and type inference — your `mutationFn`, field values, and default values are all typed from the schema automatically.

The goal is to stay out of your way when you need flexibility while giving you consistency and accessibility out of the box. Standard fields, layouts, error handling, and auto-save patterns all work the same across the app without extra wiring.

> [!TIP]
> TanStack provides an [MCP server](https://tanstack.com/form/latest/docs/mcp) that gives your AI editor access to up-to-date TanStack Form documentation. It's worth setting up if you're building forms frequently.

The form system provides two modes:

- **Submit-based forms** — Use `useScrapsForm` for traditional forms with a submit button. Best for creation flows, dialogs, and multi-field submissions.
- **Auto-save forms** — Use `AutoSaveForm` for settings pages where each field saves independently on blur or change. See [AutoSaveForm](./autoSaveForm.mdx).

For a reference of all available field components, see [Fields](./fields.mdx).

## Quick Start

A minimal form with validation and submission.

<Storybook.Demo>
  <Container width="80%">
    <QuickStartDemo />
  </Container>
</Storybook.Demo>

```jsx
import {z} from 'zod';

import {defaultFormValidators, ScrapsForm, useScrapsForm} from '@sentry/scraps/form';

const schema = z.object({
  email: z.email('Please enter a valid email'),
  name: z.string().min(2, 'Name must be at least 2 characters'),
});

function MyForm() {
  const form = useScrapsForm({
    defaultValues: {email: '', name: ''},
    validators: defaultFormValidators(schema),
    onSubmit: ({value}) => {
      console.log(value);
    },
  });

  return (
    <ScrapsForm form={form}>
      <form.Field name="name">
        {field => (
          <field.Layout.Row label={t('Name')} required>
            <field.Input value={field.value} onChange={field.handleChange} />
          </field.Layout.Row>
        )}
      </form.Field>
      <form.SubmitButton>Submit</form.SubmitButton>
    </ScrapsForm>
  );
}
```

## Form Hook: `useScrapsForm`

Create a form by calling `useScrapsForm` with your configuration. The Sentry form hook configures error visibility globally: validators run on change, but their errors stay hidden until the first submit attempt. The first invalid field is focused after an invalid submit.

```jsx
const form = useScrapsForm({
  defaultValues: {email: '', name: ''},
  validators: defaultFormValidators(schema),
  onSubmit: ({value}) => {
    // Handle submission
  },
});
```

### Returned Properties

| Property         | Description                                                                                                              |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `AppForm`        | Context wrapper. It takes children only; use the exported `<ScrapsForm form={form}>` helper for the normal form element. |
| `Field`          | Field renderer. Takes a `name` prop and a render function receiving the field API with all bound field components.       |
| `ArrayField`     | Array field renderer. Use it for array operations such as `pushValue` and `removeValue`.                                 |
| `FieldGroup`     | Section grouping with a title header. Renders a `Panel` with a `PanelHeader`.                                            |
| `SubmitButton`   | Pre-wired submit button. Automatically disables while submission is pending.                                             |
| `Subscribe`      | Subscribes to form state changes. Use `selector` to pick specific values.                                                |
| `reset()`        | Reset the form to its default values.                                                                                    |
| `handleSubmit()` | Manually trigger form submission.                                                                                        |

## Validation with Zod

Define a Zod schema and pass it in a validator array. Always provide helpful error messages.

The default policy hides errors until the first submit attempt. Use `defaultFormValidators(schema)` for form-level validation. It runs the validator on submit and on change after a submit attempt.

```jsx
const schema = z.object({
  email: z.email('Please enter a valid email'),
  password: z.string().min(8, 'Password must be at least 8 characters'),
  age: z.number().gte(13, 'You must be at least 13 years old'),
  address: z.object({
    street: z.string().min(1, 'Street is required'),
    city: z.string().min(1, 'City is required'),
  }),
});
```

### Cross-Field Validation

Use `.refine()` for validation that depends on multiple fields:

```jsx
const schema = z
  .object({
    password: z.string(),
    confirmPassword: z.string(),
  })
  .refine(data => data.password === data.confirmPassword, {
    message: 'Passwords do not match',
    path: ['confirmPassword'],
  });
```

### Per-Field Validators

For conditional validation on an individual field, use the `validators` prop on `Field`:

```jsx
<form.Field
  name="secret"
  validators={[
    {
      run: z.string().min(1, 'Secret is required'),
      triggers: ['change'],
    },
  ]}
>
  {field => (
    <field.Layout.Row label={t('Secret')} required>
      <field.Input value={field.value ?? ''} onChange={field.handleChange} />
    </field.Layout.Row>
  )}
</form.Field>
```

## Layouts

Two layout options position labels relative to fields.

### Stack Layout (Vertical)

Label above, field below. Best for forms with longer labels or when vertical space is available.

```jsx
<field.Layout.Stack
  label={t('Email Address')}
  hintText={t("We'll never share your email")}
  required
>
  <field.Input value={field.value} onChange={field.handleChange} />
</field.Layout.Stack>
```

### Row Layout (Horizontal)

Label on the left (~50%), field on the right. Compact layout for settings pages.

```jsx
<field.Layout.Row
  label={t('Email Address')}
  hintText={t('We will never share your email address')}
  required
>
  <field.Input value={field.value} onChange={field.handleChange} />
</field.Layout.Row>
```

### Compact Variant

Both layouts support `variant="compact"`, which moves hint text into a tooltip on the label instead of displaying it inline. This saves vertical space.

<Storybook.Demo maxHeight={undefined}>
  <CompactDemo />
</Storybook.Demo>

```jsx
// Default: hint text appears below the label
<field.Layout.Row label={t("Email")} hintText={t("We'll never share your email")}>
  <field.Input ... />
</field.Layout.Row>

// Compact: hint text appears in tooltip when hovering the label
<field.Layout.Row label={t("Email")} hintText={t("We'll never share your email")} variant="compact">
  <field.Input ... />
</field.Layout.Row>
```

### Layout Props

| Prop       | Type        | Description                                                           |
| ---------- | ----------- | --------------------------------------------------------------------- |
| `label`    | `ReactNode` | Field label text                                                      |
| `hintText` | `ReactNode` | Helper text. Below label by default, or in a tooltip in compact mode. |
| `required` | `boolean`   | Shows a required indicator next to the label                          |
| `variant`  | `"compact"` | Moves hint text into a tooltip instead of displaying it inline        |

### Custom Layouts

You can skip the built-in layouts and use `field.Meta.Label` and `field.Meta.HintText` directly:

```jsx
<form.Field name="firstName">
  {field => (
    <Flex gap="md">
      <field.Meta.Label required>{t('First Name')}</field.Meta.Label>
      <field.Input value={field.value ?? ''} onChange={field.handleChange} />
    </Flex>
  )}
</form.Field>
```

## Field Groups

Group related fields into titled sections using `form.FieldGroup`. It renders a `Panel` with a header and body. For reusable groups, use `defineAppFieldGroup` and bind a component to a `fields` prop; use plain `FieldGroup` inside that component.

```jsx
<form.FieldGroup title={t("Personal Information")}>
  <form.Field name="firstName">{/* ... */}</form.Field>
  <form.Field name="lastName">{/* ... */}</form.Field>
</form.FieldGroup>

<form.FieldGroup title={t("Contact Information")}>
  <form.Field name="email">{/* ... */}</form.Field>
  <form.Field name="phone">{/* ... */}</form.Field>
</form.FieldGroup>
```

## Disabled State

Fields accept `disabled` as a boolean or a string. When a string is provided, it displays as a tooltip explaining why the field is disabled.

```jsx
// Boolean — disabled without explanation
<field.Input disabled value={field.value} onChange={field.handleChange} />

// String — disabled with a reason shown as tooltip
<field.Input
  disabled={t("This feature requires a Business plan")}
  value={field.value}
  onChange={field.handleChange}
/>
```

> [!TIP]
> Prefer using a string for `disabled` so users understand why the field is not editable.

## Conditional Fields

Use `form.Subscribe` to show or hide fields based on other field values:

```jsx
<form.Subscribe selector={state => state.values.plan === 'enterprise'}>
  {showBilling =>
    showBilling ? (
      <form.Field name="billingEmail">
        {field => (
          <field.Layout.Row label={t('Billing Email')} required>
            <field.Input value={field.value ?? ''} onChange={field.handleChange} />
          </field.Layout.Row>
        )}
      </form.Field>
    ) : null
  }
</form.Subscribe>
```

## Error Handling

### Client-Side Errors

Client-side validation is automatic when using a Zod schema. Errors display as a warning icon with a tooltip in the field's trailing area.

### Server-Side Errors

Return `toFieldErrors` from `onSubmit` to display backend validation errors on specific fields:

```jsx
import {ScrapsForm, toFieldErrors, useScrapsForm} from '@sentry/scraps/form';

const form = useScrapsForm({
  defaultValues,
  onSubmit: async ({value, createValidationError}) => {
    try {
      await mutation.mutateAsync(value);
    } catch (error) {
      const fieldErrors = toFieldErrors({value, createValidationError}, error);
      if (fieldErrors) {
        return fieldErrors;
      }
      throw error;
    }
  },
});

return <ScrapsForm form={form}>{/* fields */}</ScrapsForm>;
```

For manually constructed errors, return `createValidationError` directly:

```jsx
onSubmit: async ({value, createValidationError}) => {
  try {
    await mutation.mutateAsync(value);
  } catch (error) {
    return createValidationError({
      fields: {
        email: {message: 'This email is already registered'},
        'address.city': {message: 'City not found'},
      },
    });
  }
},
```

> [!NOTE]
> Validation failures are returned from `onSubmit`. Thrown or rejected errors are submit failures. Handle transient network failures in the query layer; return `toFieldErrors` only for field validation errors.

## Form Submission

Use TanStack Query mutations (`useMutation`) for form submissions. Return the mutation promise from `onSubmit` so that `form.state.isSubmitting` stays accurate. Return a validation error for a known field failure. A thrown or rejected error is a submit failure and is handled by the form's invalid-submit path.

```jsx
import {useMutation} from '@tanstack/react-query';

import {fetchMutation} from 'sentry/utils/queryClient';

function MyForm() {
  const mutation = useMutation({
    mutationFn: (data: FormData) =>
      fetchMutation({url: '/endpoint/', method: 'POST', data}),
  });

  const form = useScrapsForm({
    defaultValues: {...},
    validators: defaultFormValidators(schema),
    onSubmit: ({value}) => mutation.mutateAsync(value),
  });

  return (
    <ScrapsForm form={form}>
      {/* fields */}
      <Flex gap="md" justify="end">
        <form.ResetButton>Reset</form.ResetButton>
        <form.SubmitButton>Save Changes</form.SubmitButton>
      </Flex>
    </ScrapsForm>
  );
}
```

`SubmitButton` automatically disables while submission is pending and triggers form validation before submitting.

## Resetting After Save

When a form stays on the page after submission (e.g., settings pages), call `form.reset()` after a successful mutation. This is necessary because `defaultValues` are reactive — when the mutation updates the cache or store, `defaultValues` update too. But if the form is dirty, the updated defaults won't be reflected in the UI until you reset.

```jsx
onSubmit: ({value}) =>
  mutation
    .mutateAsync(value)
    .then(() => form.reset()),
```

After `form.reset()`, the form re-syncs with the (now-updated) `defaultValues`, becoming pristine again. This means any UI that depends on the form being dirty (like conditionally shown Save/Cancel buttons or unsaved-changes warnings) will update correctly.

> [!NOTE]
> `AutoSaveForm` handles this automatically — it calls `form.reset()` after every successful save. You only need to add this manually when using `useScrapsForm`.

## Nullable Default Values

When a required field has no meaningful initial value (e.g., a select that starts empty), use `.nullable().refine()` in the schema. This creates a difference between the schema's input type (accepts `null`) and output type (does not). Type `defaultValues` with `z.input<typeof schema>` and call `schema.parse(value)` in `onSubmit` to narrow the type.

```jsx
import {z} from 'zod';

import {useScrapsForm} from '@sentry/scraps/form';

const schema = z.object({
  provider: z
    .enum(['GitHub', 'LaunchDarkly'])
    .nullable()
    .refine(v => v !== null, 'Provider is required'),
  name: z.string().min(1, 'Name is required'),
});

// z.input allows null for the provider field
const defaultValues: z.input<typeof schema> = {
  provider: null,
  name: '',
};

function MyForm() {
  const mutation = useMutation({
    mutationFn: (data: z.output<typeof schema>) =>
      fetchMutation({url: '/endpoint/', method: 'POST', data}),
  });

  const form = useScrapsForm({
    defaultValues,
    validators: defaultFormValidators(schema),
    onSubmit: ({value}) => {
      // schema.parse validates and narrows null away
      return mutation.mutateAsync(schema.parse(value)).catch(() => {});
    },
  });

  return (
    <ScrapsForm form={form}>
      <form.Field name="provider">
        {field => (
          <field.Layout.Row label={t('Provider')} required>
            <field.Select
              value={field.value}
              onChange={field.handleChange}
              placeholder={t('Select a provider')}
              options={[
                {value: 'GitHub', label: 'GitHub'},
                {value: 'LaunchDarkly', label: 'LaunchDarkly'},
              ]}
            />
          </field.Layout.Row>
        )}
      </form.Field>
      <form.Field name="name">
        {field => (
          <field.Layout.Row label={t('Name')} required>
            <field.Input value={field.value} onChange={field.handleChange} />
          </field.Layout.Row>
        )}
      </form.Field>
      <form.SubmitButton>Submit</form.SubmitButton>
    </ScrapsForm>
  );
}
```

> [!TIP]
> This pattern avoids non-null assertions (`value.provider!`) and type casts. The `schema.parse()` call is both type-safe and validates at runtime, ensuring your mutation always receives the correct type.
