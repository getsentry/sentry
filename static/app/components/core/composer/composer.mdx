`<Composer>` keeps editable text and structured references in one controlled value. Behavior is attached with plugins: each plugin contributes suggestion sources that provide their own data, identity, inserted text, and suggestion presentation.

A native `<textarea>` handles text, selection, undo, input methods, and mobile keyboards. Its own text is transparent: a mirror laid exactly over it draws the visible text and the inline mentions. The `ref` points at the textarea.

## Compose with multiple sources

A plugin groups related sources under a stable `id`. This example combines local member and team sources. Selected references render inline as mentions while their range is valid.

Suggestion objects stay within their source. The controlled value stores only stable IDs and text ranges.

<Storybook.Demo overflow="visible">
  <ComposerDemo />
</Storybook.Demo>

```jsx
const mentionPlugin = {
  id: 'mentions',
  getSources: () => [
    {
      id: 'members',
      label: 'Members',
      trigger: '@',
      getSuggestions: query => filterPeople(query),
      getId: person => person.id,
      getText: person => `@${person.label}`,
    },
    {
      id: 'teams',
      label: 'Teams',
      trigger: '#',
      getSuggestions: query => filterTeams(query),
      getId: team => team.id,
      getText: team => `#${team.slug}`,
    },
  ],
};

<Composer
  aria-label="Comment"
  minHeight={120}
  plugins={[mentionPlugin]}
  value={value}
  onChange={setValue}
/>;
```

## Render mentions inline

Sources can provide `renderMention` to draw a mention as a component, such as a member's avatar. Sources without it render mentions as highlighted text.

The caret moves through the textarea's text, not through the component, so the component is drawn over the mention's text and clipped to it. It must fit the width of `mention.text` in the editor font: keep the text and swap glyphs instead of adding padding or margins. In the example, the avatar takes the place of the `@` glyph. When a mention wraps across lines, Composer shows its text instead. Narrow the editor to see the fallback.

Mentions render behind `pointer-events: none`, so they cannot be interactive.

<Storybook.Demo overflow="visible">
  <InlineMentionsDemo />
</Storybook.Demo>

```jsx
function MemberMention({mention}) {
  return (
    <span>
      {/* The transparent `@` reserves exactly its own width for the avatar. */}
      <TriggerSlot>
        {mention.text.charAt(0)}
        <UserAvatar size={12} user={getMember(mention.id)} />
      </TriggerSlot>
      {mention.text.slice(1)}
    </span>
  );
}

const memberSource = {
  id: 'members',
  label: 'Members',
  trigger: '@',
  getSuggestions: query => filterPeople(query),
  getId: person => person.id,
  getText: person => `@${person.label}`,
  renderMention: mention => <MemberMention mention={mention} />,
};
```

## Edit around mentions

Mentions are atomic:

- **Backspace** after a mention, or **Delete** before it, removes the whole mention.
- Deleting or replacing a selection that covers part of a mention removes the whole mention.
- The caret never rests inside a mention. Arrow keys skip over it, and a click inside it moves the caret to the nearest edge.
- Undo and redo restore the mentions that existed when the text was last in that state.

Edits the editor makes itself, such as inserting a selected suggestion or removing a whole mention with Backspace, join the browser's undo history.

## Share a trigger between sources

Sources sharing a trigger character contribute suggestions to the same popup, and selecting an option resolves the source that owns it — so each source keeps its own inserted text and suggestion identity. Use this to offer several kinds of references under one affordance, such as members and teams on `@`.

<Storybook.Demo overflow="visible">
  <SharedTriggerDemo />
</Storybook.Demo>

```jsx
const mentionPlugin = {
  id: 'mentions',
  getSources: () => [
    {
      id: 'members',
      label: 'Members',
      trigger: '@',
      queryOptions: query => searchMembersQueryOptions(query),
      getId: person => person.id,
      getText: person => `@${person.label}`,
    },
    {
      id: 'teams',
      label: 'Teams',
      trigger: '@',
      getSuggestions: query => filterTeams(query),
      getId: team => team.id,
      getText: team => `@${team.slug}`,
    },
  ],
};

<Composer
  aria-label="Comment"
  plugins={[mentionPlugin]}
  value={value}
  onChange={setValue}
/>;
```

A trigger group supports any number of local sources and at most one async source.

## Load queried suggestions

Async sources provide TanStack Query options, sharing the application's loading, caching, cancellation, and error behavior. In this example, queries take half a second, and queries starting with `fail` show the error state.

<Storybook.Demo overflow="visible">
  <AsyncComposerDemo />
</Storybook.Demo>

```jsx
const remotePlugin = {
  id: 'remote-members',
  getSources: () => [
    {
      id: 'remote-members',
      label: 'Remote members',
      trigger: '@',
      queryOptions: query =>
        queryOptions({
          queryKey: ['members', query],
          queryFn: () => searchMembers(query),
          staleTime: Infinity,
        }),
      getId: person => person.id,
      getText: person => `@${person.label}`,
    },
  ],
};

<Composer
  aria-label="Remote member search"
  plugins={[remotePlugin]}
  value={value}
  onChange={setValue}
/>;
```

## Commands instead of references

Sources providing `onSelect` run a custom action on selection instead of inserting text at the trigger position — for command-style triggers that clear the editor, insert a snippet, or toggle a mode. Pair it with `restrictToStart` so the trigger only matches at the very start of the editor's text, like a slash command.

Provide either `getText` or `onSelect`, never both. Call at most one editor action synchronously inside `onSelect`, before any `await`. Actions capture the value and trigger range at selection: `insertText` replaces that range with plain text, and repeated calls do not build on earlier edits. Do not retain actions for later use; asynchronous updates belong in the owner's controlled value.

<Storybook.Demo overflow="visible">
  <CommandComposerDemo />
</Storybook.Demo>

```jsx
const commandPlugin = {
  id: 'commands',
  getSources: () => [
    {
      id: 'commands',
      label: 'Commands',
      trigger: '/',
      restrictToStart: true,
      getSuggestions: query =>
        COMMANDS.filter(command => command.title.startsWith(query)),
      getId: command => command.id,
      renderSuggestion: command => `/${command.title}`,
      onSelect: (command, actions) => {
        if (command.id === 'clear') {
          actions.clear();
        } else {
          actions.insertText("Thanks for reaching out — I'll take a look shortly.");
        }
      },
    },
  ],
};

<Composer
  aria-label="Command input"
  placeholder="Type / for commands"
  plugins={[commandPlugin]}
  value={value}
  onChange={setValue}
/>;
```

## Submit on Enter

Composer passes `onKeyDown` through once its own keys are handled. Enter and Tab pick a suggestion while the popup is open, and keys pressed while an input method is composing never reach `onKeyDown`, so a handler can submit on Enter without checking either.

<Storybook.Demo overflow="visible">
  <SubmitComposerDemo />
</Storybook.Demo>

```jsx
<Composer
  aria-label="Message"
  plugins={[mentionPlugin]}
  value={value}
  onChange={setValue}
  onKeyDown={event => {
    if (event.key === 'Enter' && !event.shiftKey && value.text.trim() !== '') {
      event.preventDefault();
      send(value);
      setValue({text: '', mentions: []});
    }
  }}
/>
```
