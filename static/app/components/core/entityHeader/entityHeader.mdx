`EntityHeader` shows the key facts about one entity, such as a replay, an issue or a build, in a band at the top of its detail page. Layout responds to its container through [container queries](/scraps/core/container/#container-queries), and every slot has a built-in [loading skeleton](/scraps/product/components/placeholder/).

```jsx
<EntityHeader title={{type: 'text', label: t('Issue type'), value: issue.type}} />
```

## When to use

Use it directly below the TopBar on a page about a single entity.

> [!NOTE]
> `EntityHeader` does not render breadcrumbs, the page `h1` or global actions. Those belong to the TopBar's slots (`TopBar.Slot name="breadcrumbs"` / `"title"`). The title here is an `h2`.

## Usage

The header has five slots: `title`, `subtitle`, `stats`, `people` and `metadata`. Only `title` is required, and the layout is built from whichever others you pass, so an omitted slot leaves no empty row.

The example below is the Replay Details header. The title links to the replays list filtered to this user, Dead Clicks and Rage Clicks link to the breadcrumbs tab, and the error count carries a breakdown in its tooltip.

`stats.items`, `metadata.items` and `title.tags` skip an entry that is `null` itself, so a whole item can be written as an inline conditional. This is separate from a stat's `value: null`: that item is still there, and shows "No data" (see [No data](#no-data)). Items are keyed by their position in the array you wrote, so one appearing or disappearing never remounts its neighbors.

```jsx
<EntityHeader
  title={title}
  stats={{
    label: t('Replay stats'),
    items: [
      // Left out on a video replay, which has no clicks to count
      isVideoReplay ? null : {label: t('Dead Clicks'), value: deadClicks},
      // Always there; `build.cost` is `null` when no cost was recorded,
      // which shows "No data"
      {label: t('Cost'), value: build.cost},
    ],
  }}
/>
```

## Loading

Pass `isLoading` and every declared slot renders a skeleton instead: one per stat or metadata item (`null` metadata items included), at the fixed height of the line it will hold. A stat is held as a single block, and the title's graphic and tags wait until it loads.

While `isLoading` is set, a declared `metadata` keeps its row even if every item is still `null`, so the page below does not jump when the facts land together. Once loading ends, a `metadata` whose items are all `null` leaves no row, the same as an omitted one. `subtitle` has nothing to declare, so its line appears when its text does.

> [!NOTE]
> Skeleton widths aren't configurable.

## Title

A title needs a `label` and a `value`. The `value` is shown; the `label` is read first by screen readers to say what the value is.

```jsx
<EntityHeader
  title={{type: 'text', label: t('Replay user'), value: replay.user.display_name}}
/>
```

### Types

A title is `text` or `link`. A `link` points the entity's name at the list it came from, filtered to it. Use `to` inside the product, or `externalHref` for a destination outside it, which opens in a new tab. Only link a title when the destination is obvious from the title itself.

```jsx

// Link inside the product
```

A link title is accent-colored with no underline. The link wraps the `h2`, so a headings list and a links list both read "Replay user, anonymous@example.com".

## Stats

A stat is one measurement: a `label` naming it and a `value`, shown side by side with the label first. Keep the value to the single number the label names, and put any breakdown in a tooltip.

```jsx
<EntityHeader
  title={title}
  stats={{label: t('Replay stats'), items: [{label: t('Rage Clicks'), value: 2}]}}
/>
```

### Types

Each half, `label` and `value`, is `text` or `link`. A string (or, for `value`, a number or `null`) is shorthand for `text`. The object form is `{type, content, tooltip?}`, and a `link` adds `to` or `externalHref`, plus an optional `onClick` for analytics.

```jsx
items: [
  // Shorthand
  {label: t('Rage Clicks'), value: 2},

  // The label links: the destination is about what is measured
  {
    label: {type: 'link', content: t('Dead Clicks'), to: breadcrumbsTab},
    value: deadClicks,
  },

  // The value links: the destination is the things it counts
  {
    label: t('Errors'),
    value: {type: 'link', content: errorCount, to: errorsUrl, onClick: trackErrorsClick},
  },

  // A link outside the product
  {
    label: {type: 'link', content: t('Install Size'), externalHref: sizeDocsUrl},
    value: installSize,
  },
];
```

> [!WARNING]
> Don't switch a half between `text` and `link` based on its data. A half that became a link once its data arrived would gain a tab stop and a link role mid-load. A link stays a link when its count is zero or empty.

Color is set by the header, not the caller: a text label is muted, a text value uses the default color (muted when it's `null`), a link half is accent, and stats take no `variant`.

Both halves can link, to the same place or to different ones. Two links to the same place add a second tab stop for nothing, so prefer one.

### Tooltips

Set `tooltip` on the half it explains; this needs the object form. On a label, explain jargon. On a value, show a breakdown, such as errors by project. Content can be built from `Tooltip.Header`, `Tooltip.Grid` and `Tooltip.Row`.

Accent color means a half navigates; an underline means it has a tooltip. A half can be both, as below.

### No data

Pass `value: null` when the stat applies but its data was never collected, such as a build with no cost recorded. It shows a muted "—" and is read as "No data". Four states are easy to confuse:

- **No data:** `value: null`. The data will not arrive later; if it will, the stat is loading.
- **Zero:** `value: 0`. A real measurement.
- **Loading:** `isLoading`. Shows a skeleton, not a dash.
- **Does not apply:** `null` for the whole item, which leaves the stat out.

> [!WARNING]
> Don't pass a placeholder such as `'-'`, `'—'` or `'N/A'`. A screen reader reads it aloud as the value ("dash"). The header warns in development when it sees one.

An empty `link` value stays a link, colored accent rather than muted, and is read "No data". Give the reason there is no value in the value's `tooltip`, as plain text.

## Metadata

The metadata row is a list of properties that wraps onto as many lines as it needs, with a small (`md`) gap between boxes. Every property but the last ends with a pipe, drawn inside it after the value, so the pipe wraps with its property. When the row wraps, a line can end on a pipe. Each item has a `label` saying what it is and a `value`. Add `secondary` for a qualifier such as a browser's version rather than joining both into one string; its `label` composes with the parent's, so "version" under "Browser" is read "Browser version". A property needing a third value is two properties.

`type: 'link'` makes the value a link, with `to` or `externalHref` as on the title. Its name includes the key ("Release 8.42.0"), because the key is usually hidden. `tooltip` explains the value on hover or focus, with an underline. `mode: 'full'` draws the key beside the value; the default, `compact`, keeps it for screen readers only.

Each header below varies one thing: the first shows how mode and a leadingGraphic combine, the second compares a value with and without a secondary qualifier, and the third shows the kinds of value.

### Lists

`type: 'list'` holds several entries under one key, such as the tools a conversation called. Each entry is a text or link metadata value with a `key`, and draws the way a metadata item does, so it takes its own `variant`, `tooltip`, `secondary` and `leadingGraphic`. An entry cannot be a list. `maxVisible` caps how many are shown and collapses the rest behind "+N more", which lists them on hover or focus. It is responsive: plain keys resolve against the header's width, `screen:` keys against the viewport. `filter` then `sort` run before the cut, so the entries that matter stay in view. A list takes no `tooltip`, `secondary` or `variant` of its own, and renders nothing once `filter` leaves it empty. Its entries flow into the metadata row and wrap with it, as if each were a property. What groups them is that no pipe falls between them. The list's `leadingGraphic` and, in `full` mode, its label travel with the first entry. Its pipe follows its last visible element, "+N more" when entries are collapsed and the last entry otherwise, unless the list is the row's last property. A list that `filter` empties counts as absent, so the property before it ends the row without a pipe.

export const tools = [
  {name: 'search_flights', hasError: false},
  {name: 'book_hotel', hasError: true},
  {name: 'get_weather', hasError: false},
  {name: 'convert_currency', hasError: false},
  {name: 'translate', hasError: true},
  {name: 'find_restaurants', hasError: false},
  {name: 'internal_ping', hasError: false},
];
export const erroredTools = new Set(
  tools.filter(tool => tool.hasError).map(tool => tool.name)
);

## Accessibility

- **Title:** an `h2`, named "label, value" ("Replay user, anonymous@example.com"). A link title carries the same name.
- **Lists:** the stats and metadata rows are lists, each named by its `label` ("Replay stats", "Replay properties"). People sit beside the stats list, not inside it.
- **Stats:** the label comes before the value on screen and in the DOM, and each half is read as shown: "Errors", then "3". A link is named by its own text, so a label link reads "Errors" and a value link reads "3". The other half, in the same list item, gives the context.
- **Tab order:** only halves that link or have a tooltip are tab stops, label first. A tooltip on a link attaches to the link, so it adds no extra stop.
- **No data:** the dash is hidden from screen readers and "No data" is read instead.
- **People:** read as text ("Viewed by: Alice Chen, Bob Diaz"). The avatars are decorative and can't be focused.
- **Metadata:** every key is in the DOM, as hidden text or in a link's name, so a value is never announced unexplained: "Browser, Chrome, Browser version, 144.0.0". Leading graphics are hidden from assistive technology, and the pipes that end properties are decorative and never announced.
- **Metadata lists:** a nested list named by its `label`. Collapsed entries stay in it, visually hidden, so a screen reader hears every entry and the true count. Collapsed entries are read-only: a link reads as text and a tooltip is dropped, so nothing hidden is a tab stop. "+N more" is the list's last item, read after every entry, and the only tab stop for the collapsed entries. It opens them in a tooltip.
- **Color:** accent marks a link and an underline marks a tooltip. Links also show a focus ring on keyboard focus, so a keyboard user does not have to rely on color alone.
- **Loading:** the header sets `aria-busy` while any slot is loading. This is a state, not an announcement.

### Developer responsibilities

- Always pass a `label` for `stats`, `people` and `metadata`. Without one, a screen reader meets a run of values with nothing saying what they belong to.
- Give a title's `leadingGraphic` a `label` when it adds information the title does not have.
- Use `value: null` for no data, never a placeholder string.
- Don't put anything a user needs only in a tooltip. Nothing inside a tooltip can be reached by keyboard, and screen readers may not announce it.
- Add your own live region if the end of loading needs to be announced.
