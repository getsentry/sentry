`<FingerprintRulesEditor>` is a textarea for [fingerprint rules](https://docs.sentry.io/product/data-management-settings/event-grouping/fingerprint-rules/). It highlights each part of a rule, and underlines mistakes that would stop the rules from saving or make them behave differently than they read.

The highlighting is a layer over the textarea, whose own text is transparent, so typing, selection, undo, and autosize all stay native. The tokenizer in `fingerprintRulesSyntax.ts` follows the backend grammar, so a config gets an error when the backend can't parse it. It doesn't check matcher or variable names, so it never goes stale when the backend adds one. The backend still validates on save, so if the tokenizer throws, the editor quietly shows plain text and reports the error.

## Highlighting

Matchers are on the left of `->`, and the fingerprint is on the right. Variables like `{{ default }}` are filled in from the event.

<Storybook.Demo>
  <EditorDemo initialValue={validRules} />
</Storybook.Demo>

```tsx
<FingerprintRulesEditor value={rules} onChange={setRules} rows={2} maxRows={20} />
```

## Catching Mistakes

Errors (red) stop the rules from saving, and warnings (yellow) save but probably don't do what was meant. Expand the summary below the field to see what's wrong, and pick a line to select it. Problems show up once typing pauses, so a half-written rule isn't flagged.

## Long Configs

Past `maxRows`, the textarea scrolls and the highlighting scrolls with it.

## Accessibility

The highlighting layer is hidden from assistive technology. The error and warning counts are linked to the textarea with `aria-describedby`, and the expanded list explains every problem.
