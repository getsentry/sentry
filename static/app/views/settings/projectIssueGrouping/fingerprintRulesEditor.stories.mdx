`<FingerprintRulesEditor>` is a textarea for [fingerprint rules](https://docs.sentry.io/product/data-management-settings/event-grouping/fingerprint-rules/). It highlights each part of a rule, and underlines mistakes that would stop the rules from saving or make them behave differently than they read.

The highlighting is a layer over the textarea, whose own text is transparent, so typing, selection, undo, and autosize all stay native. The tokenizer in `fingerprintRulesSyntax.ts` follows the backend grammar, so a config gets an error when the backend would reject it.

## Highlighting

Matchers are on the left of `->`, and the fingerprint is on the right. Variables like `{{ default }}` are filled in from the event.

<Storybook.Demo>
  <EditorDemo initialValue={validRules} />
</Storybook.Demo>

```tsx
<FingerprintRulesEditor value={rules} onChange={setRules} rows={2} maxRows={20} />
```

## Catching Mistakes

Errors (red) stop the rules from saving, and warnings (yellow) save but probably don't do what was meant. Hover an underline to see what's wrong, or expand the summary to list them all. Problems show up once typing pauses, so a half-written rule isn't flagged.

## Missing Closing Quote

A quoted value can span lines, so a missing closing quote swallows the following rules until the next quote.

## Read-Only

`<FingerprintRulesCode>` shows highlighted rules that can't be edited, like the example on the Issue Grouping settings page.

<Storybook.Demo>
  <FingerprintRulesCode rules={validRules} />
</Storybook.Demo>

```tsx

```

## Accessibility

The highlighting layer is hidden from assistive technology. The error and warning counts are linked to the textarea with `aria-describedby`, and the expanded list reaches every problem without hovering.
