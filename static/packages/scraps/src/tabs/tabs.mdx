`<Tabs>` manages tab selection and gives its child function typed `TabList` and `TabPanels` components. It uses React Aria for keyboard navigation and accessibility, and moves tabs into an overflow menu when needed.

Use `<Tabs>` to organize related content into separate views that users can switch between without leaving the page.

```jsx
<Tabs>
  {({TabList, TabPanels}) => (
    <Flex direction="column" flexGrow={1} minWidth="0" flexBasis="0" alignSelf="stretch">
      <TabList>
        <TabList.Item key="tab1">Tab 1</TabList.Item>
        <TabList.Item key="tab2">Tab 2</TabList.Item>
      </TabList>
      <TabPanels>
        <TabPanels.Item key="tab1">Content for Tab 1</TabPanels.Item>
        <TabPanels.Item key="tab2">Content for Tab 2</TabPanels.Item>
      </TabPanels>
    </Flex>
  )}
</Tabs>
```

## Compound Components

Import only `Tabs`. Get `TabList` and `TabPanels` from its child function. These components share the string key type of that `Tabs` instance. Use matching string keys for each tab and its panel. Numeric keys are not supported.

- **`<Tabs>`**: Root component that manages state and provides context without adding a DOM element
- **`<TabList>`**: Container for tab buttons
- **`<TabList.Item>`**: Individual tab button
- **`<TabPanels>`**: Container for tab content panels
- **`<TabPanels.Item>`**: Individual content panel

> [!NOTE]
> Only the selected panel content is mounted. Switching tabs unmounts the previous panel. Store state outside the panel if it must survive a tab change.

## Layout

`Tabs` adds no DOM element or layout styles. Use `Flex`, `Grid`, or an existing parent to arrange the list and panels. The examples use a column `Flex` for horizontal tabs and a row `Flex` for vertical tabs. Put sizing, spacing, and alignment props on that layout component.

## Basic Usage

The simplest tabs implementation with automatic state management:

export function BasicDemo() {
  const TABS = [
    {key: 'one', label: 'Label 1', content: 'This is the first panel.'},
    {key: 'two', label: 'Label 2', content: 'This is the second panel.'},
    {key: 'three', label: 'Label 3', content: 'This is the third panel.'},
  ];
  return (
    <Tabs>
      {({TabList, TabPanels}) => (
        <Flex
          direction="column"
          flexGrow={1}
          minWidth="0"
          flexBasis="0"
          alignSelf="stretch"
        >
          <TabList>
            {TABS.map(tab => (
              <TabList.Item key={tab.key}>{tab.label}</TabList.Item>
            ))}
          </TabList>
          <TabPanels>
            {TABS.map(tab => (
              <TabPanels.Item key={tab.key}>{tab.content}</TabPanels.Item>
            ))}
          </TabPanels>
        </Flex>
      )}
    </Tabs>
  );
}

## Controlled Tabs

For controlled tabs, use `value` and `onChange` to manage the active tab externally. `value` determines the allowed item keys and the `onChange` parameter type. Use a union for known keys.

    <Fragment>

## Linked tabs

Set `to` on `TabList.Item` to render a link. Derive `Tabs.value` from the current route so navigation selects the matching tab, including links in the overflow menu.

Arrow keys move focus between links. Press Enter or Space, or click a link, to navigate. Automatic selection does not navigate to a link.

This demo uses `nuqs` to read the `linkedTab` query parameter and build link URLs that keep navigation on this page. Resize the demo to test overflow. Ctrl-click or Command-click a link to open it in a new browser tab.

export function LinkedTabsDemo() {
  const location = useLocation();
  const tabs = [
    {key: 'overview', label: 'Overview'},
    {key: 'activity', label: 'Activity'},
    {key: 'feedback', label: 'User Feedback'},
    {key: 'attachments', label: 'Attachments'},
    {key: 'settings', label: 'Settings'},
  ];
  const parser = parseAsStringLiteral(tabs.map(({key}) => key)).withDefault('overview');
  const [value] = useQueryState('linkedTab', parser);
  const serialize = createSerializer({linkedTab: parser});
  return (
    <Tabs value={value}>
      {({TabList, TabPanels}) => (
        <Flex
          direction="column"
          flexGrow={1}
          minWidth="0"
          flexBasis="0"
          alignSelf="stretch"
        >
          <TabList aria-label="Linked tabs">
            {tabs.map(({key, label}) => (
              <TabList.Item
                key={key}
                to={{
                  search: serialize(location.search, {linkedTab: key}),
                  hash: location.hash,
                }}
              >
                {label}
              </TabList.Item>
            ))}
          </TabList>
          <TabPanels>
            {tabs.map(({key, label}) => (
              <TabPanels.Item key={key}>{label} content</TabPanels.Item>
            ))}
          </TabPanels>
        </Flex>
      )}
    </Tabs>
  );
}

## Keyboard Navigation

`<Tabs>` provides full keyboard support automatically:

- **Arrow Left/Right** (horizontal) or **Arrow Up/Down** (vertical): Navigate between tabs
- **Home**: Jump to first tab
- **End**: Jump to last tab
- **Tab**: Move focus out of tab list
- **Enter/Space**: Activate focused tab

## Accessibility

`<Tabs>` is built with React Aria and automatically meets WCAG 2.2 AA standards:

- [2.1.1 Keyboard](https://www.w3.org/TR/WCAG22/#keyboard): Full keyboard navigation
- [2.4.7 Focus Visible](https://www.w3.org/TR/WCAG22/#focus-visible): Clear focus indicators
- Follows the [WAI-ARIA Tabs pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)

The component automatically includes:

- `role="tablist"`, `role="tab"`, and `role="tabpanel"`
- `aria-selected` state management
- `aria-controls` linking tabs to panels
- `aria-labelledby` linking panels to tabs
- Proper focus management

### Developer Responsibilities

**Meaningful Tab Labels**

- Tab labels should be concise and descriptive
- Avoid generic labels like "Tab 1" in production

```jsx
// Good: Descriptive labels
<TabList.Item key="overview">Overview</TabList.Item>
<TabList.Item key="activity">Activity Feed</TabList.Item>

// Bad: Generic labels
<TabList.Item key="tab1">Tab 1</TabList.Item>
```

**Content Organization**

- Keep related content together in tabs
- Don't use tabs for sequential workflows (use a wizard/stepper instead)
- Limit to 5-7 tabs maximum for usability

**State Preservation**

- Only the selected panel content is mounted
- Switching tabs unmounts the previous panel and mounts the next panel
- Keep form data or other shared state above `Tabs` when it must survive tab changes

For more information, see the [WAI-ARIA Tabs practices](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/).
